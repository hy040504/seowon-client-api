1. 프로젝트 개요

이 프로젝트는 서원대학교 e-campus 사이트를 대상으로 하는 TypeScript 기반 클라이언트 라이브러리다.
핵심 목적은 다음과 같다.

- 로그인용 encryptData 생성
- e-campus 로그인 요청 및 응답 해석
- 로그인 후 메인 페이지에서 과목 목록 추출
- 과목별 강의실 코드(crsCreCd)와 과목 구분(crsTypeCd) 추출
- 강의실의 공지사항, 과제, 강의자료실 목록 추출
- Fiddler SAZ 패킷에서 목록 데이터를 복원
- 쿠키를 파일에 저장하고 만료 시 자동 재로그인

현재는 단순 파서 수준을 넘어, 실제 로그인 흐름과 강의실 목록 조회 흐름까지 모듈화되어 있다.

3. 현재 구현 상태

3-1. 로그인

`EcampusClient`는 다음 흐름을 지원한다.

1. 로그인 페이지 접속
2. 쿠키 확보
3. `createLoginEncryptData()`로 `encryptData` 생성
4. `/user/userHome/login`으로 로그인 요청
5. 응답을 `redirect | reload | error`로 해석

추가로 다음 기능이 있다.

- `cookieFilePath`가 있으면 쿠키를 파일에 저장
- 저장된 쿠키가 만료되면 `loginCredentials`로 재로그인
- `getMainPageHtml()`, `postForm()` 호출 시 자동으로 재인증 확인

3-2. 과목 목록

메인 페이지 HTML에서 다음 형태의 과목 목록을 뽑는다.

```json
[
  { "title": "논리회로", "crsCreCd": "2026_1_736078_01", "crsTypeCd": "UNI" },
  { "title": "2026년 교제폭력 예방교육", "crsCreCd": "CE_260304T150804_e192529", "crsTypeCd": "CO" }
]
```

구분 기준은 `crsTypeCd`다.

- `UNI` = 교과
- `CO` = 비교과

프론트 기준으로는 `classRoomMain(crsCreCd, crsTypeCd)` onclick 값을 읽어온다.

3-3. 강의실 목록

현재 세 가지를 분리해서 제공한다.

- `getNoticeList()` / `getNoticeListJson()`
- `getAssignmentList()` / `getAssignmentListJson()`
- `getMaterialList()` / `getMaterialListJson()`

각 항목은 보통 아래 정보를 가진다.

- `id`
- `title`
- `url`
- `request`
- `date`
- `period`
- `status`
- `hasAttachment`

목록은 GET 링크가 아니라 POST 렌더링 방식인 경우가 많아서, `request.method`와 `request.body`도 같이 반환한다.

3-4. SAZ 복원

패킷 파일에서 공지사항/과제/강의자료실 목록을 복구할 수 있다.

지원 함수 예시:

- `parseEcampusNoticeListFromSaz()`
- `parseEcampusAssignmentListFromSaz()`
- `parseEcampusMaterialListFromSaz()`
- `parseEcampusClassroomResourcesFromSaz()`

3-5. e-learning

온라인 강의 화면은 읽기 전용 분석 흐름으로 정리되어 있다.

- 강의 목록 파싱: `parseEcampusLessonSchedulesHtml()`, `parseEcampusLessonListHtml()`
- 강의 창 파싱: `parseEcampusLessonStudyWindowHtml()`
- SAZ 복원: `parseEcampusLessonSchedulesFromSaz()`, `parseEcampusLessonListFromSaz()`, `parseEcampusLessonStudyWindowsFromSaz()`
- 요청 생성: `createLessonViewRequest()`, `createLessonStudyWindowRequest()`, `createStudyRecordRequest()`
- 읽기 전용 스냅샷: `parseStudyRecordSnapshot()`
- 묶음 생성: `createEcampusLessonRequestBundle()`

중요한 경계:

- 실제 학습기록을 사람처럼 자동 전송하는 기능은 구현하지 않는다.
- 현재 기능은 요청 구조를 분석하고, 필요한 값과 JSON 형태를 정리하는 데 초점이 있다.

4. 쿠키 저장 방식

현재 쿠키는 메모리만 쓰는 방식이 아니라 파일 저장을 지원한다.

핵심 동작:

- `cookieFilePath`가 있으면 `tough-cookie` `CookieJar`를 JSON으로 저장
- 파일에 저장된 쿠키가 살아 있으면 그대로 사용
- 만료되었으면 `loginCredentials`로 재로그인

관련 함수:

- `loadCookieJarFromFile(filePath)`
- `saveCookieJarToFile(filePath, cookieJar)`
- `isSerializedCookieJarUsable(serialized)`
- `isCookieJarUsable(cookieJar)`

주의:

- `loginCredentials` 없이 만료 쿠키만 들어 있으면 자동 재로그인을 할 수 없다.
- 쿠키 파일은 실제 계정 세션을 담으므로 저장 위치를 분명히 관리해야 한다.

8. 핵심 데이터 의미

- `crsCreCd`
  - 과목/강의실 고유 코드
- `crsTypeCd`
  - `UNI`: 교과
  - `CO`: 비교과
- `BBS_${crsCreCd}_N`
  - 공지사항 게시판 ID
- `BBS_${crsCreCd}_P`
  - 강의자료실 게시판 ID

9. 다음 AI가 바로 이어서 보면 좋은 점

1. 문서와 테스트는 이미 꽤 안정화되어 있다.
2. 새 기능을 붙일 때는 `src/ecampus/login.ts`의 자동 재로그인 흐름을 먼저 확인하는 편이 좋다.
3. SAZ 파싱은 프론트 구조와 패킷 구조 둘 다 영향을 받으니, 실제 HTML/패킷 샘플을 같이 보는 것이 안전하다.
4. 과목/강의실/게시판 구조가 바뀌면 `crsCreCd`, `crsTypeCd`, `bbsId` 규칙부터 다시 확인해야 한다.

10. 남은 확장 후보

- 과목명으로 바로 공지/과제/자료 조회하는 편의 API
- 강의실 상세 페이지 진입 후 첨부파일 URL까지 포함한 파싱
- 쿠키 파일 저장 경로 기본값 정리
- 비교과(`CO`) 강의실에 대한 추가 화면 파싱

- e-learning 읽기 전용 스냅샷을 로컬 분석 로그로 저장하는 보조 API

11. 주의사항

- 실제 로그인 계정 정보는 `.env` 밖으로 노출하지 않는다.
- 쿠키 파일은 민감 정보이므로 저장 위치를 git 추적 대상에서 제외하는 편이 좋다.
- 패키지 테스트는 `node test/*.ts`가 아니라 `vitest` 기준으로 실행해야 한다.
