[1. 프로젝트 개요]

서원대학교 e-campus(LMS)에 로그인하고 과목, 공지, 강의자료, 과제, 이러닝 차시, 영상 주소 분석, 영상 다운로드, 학습 기록 갱신을 처리하는 TypeScript 클라이언트와 CLI 도구 세트입니다.

공식 LMS SDK가 아니라 화면 흐름과 HTTP 요청을 분석해 만든 비공식 클라이언트입니다. 계정 정보, 쿠키, LMS HTML, 패킷 캡처를 외부에 노출하지 않아야 합니다.

[2. 실행 환경]

- Node.js 20+
- npm
- ESM 패키지: package.json의 "type": "module"
- TypeScript strict mode
- Windows PowerShell 기준으로 개발 및 확인

주요 환경 변수:

- SEOWON_ID: 아이디 또는 학번
- SEOWON_PASSWORD: 비밀번호
- DOWNLOAD_HIGH_WATER_MARK: 다운로드 쓰기 버퍼 크기(KB), 기본값 1024

[3. 실행 도구]

1) npm run prompt:client

개별 API 응답과 파싱 결과를 직접 확인하는 진단용 CLI입니다.

지원 명령:

- login
- courses
- notices
- materials
- assignments
- classroom-resources
- elearning-lessons
- elearning-open
- elearning-mp4
- elearning-download
- elearning-watch
- help

elearning-watch는 학습 세션 시작 후 유지 모드로 들어갑니다. 중단 시 Ctrl+C를 사용합니다.

2) npm run auto:manager

반복 작업 처리용 CLI입니다.

현재 메뉴:

1. 로그인 / 로그인 정보 갱신
2. 이러닝 일괄 다운로드 (전체 대기열 시각화)
3. 이러닝 순차 자동 시청 (고급 로그 제어)
4. 전체 교과목 미제출 과제 전수 조사
5. 전 과목 기간 내 미완료 이러닝 자동 시청
6. 현재 수행 가능한 전 과목 미제출 과제 목록
7. 현재 수행 가능한 과제 선택 및 상세내용 보기
8. 강의자료 다운로드 (일괄 + 첨부 분석/미리보기)
0. 종료

[4. auto-manager 최신 동작]

1) 로그인과 자동 재로그인

- 시작 시 .seowon-ecampus.cookies.json을 불러옵니다.
- 유효한 쿠키가 있으면 기존 세션을 재사용합니다.
- 작업 중 SESSION_EXPIRED 또는 "로그인" 포함 오류를 만나면 저장 계정 또는 .env로 재로그인합니다.
- 재로그인 성공 시 원래 작업을 한 번 다시 실행합니다.

2) 이러닝 다운로드

- 선택한 과목의 여러 차시를 큐에 넣습니다.
- 동시 다운로드 수는 사용자 입력을 받고 1~5 범위로 제한합니다.
- 저장 경로는 downloads/<과목명>/<차시명>.mp4입니다.
- DOWNLOAD_HIGH_WATER_MARK를 KB 단위로 읽어 스트림 쓰기 버퍼로 사용합니다.
- 메뉴 2 다운로드 선택 목록과 다운로드 진행 큐에는 [n 주차] 접두어를 표시합니다.
- 실제 다운로드 파일명은 기존 차시명 그대로 유지합니다.

3) 순차 자동 시청

- 메뉴 3은 한 과목에서 선택한 차시를 순차 처리합니다.
- 메뉴 5는 전 과목에서 현재 수강 기간 안에 있고 상태가 학습중(지각) 또는 미학습(결석)인 차시를 찾습니다.
- 메뉴 5의 자동 시청 확인 기본값은 Y입니다.
- 각 차시는 durationSeconds 동안 유지하고, 값이 없으면 3600초를 사용합니다.
- 메뉴 3 선택 목록, 메뉴 5 대상 목록, 시청 대기 문구에는 [n 주차] 접두어를 표시합니다.
- 이러닝 주차는 src/ecampus/elearning.ts의 EcampusLessonItem.scheduleTitle에 저장된 주차 묶음 제목에서 읽습니다.

TTY 터미널에서는 3줄 고정 상태 영역을 사용합니다.

[ElearningSession] 학습 중... (서버 학습 률: 31.6%, 누적 180초) ⠴
[ElearningSession] 학습 이력 갱신 대기 중...
|████████████░░░░░░░░░░░░░░░░░░░░░░░░░░░░|  31.6% 15분 48초 / 50분 0초

- 첫 번째 줄: addStudyRecord 응답의 prgrRatio 기반 서버 학습률, 누적 시간, ⠋ ⠙ ⠹ ⠸ ⠼ ⠴ 스피너
- 서버 학습률 표시값은 소수점 문자열이 반환되면 소수점 형식을 유지
- 두 번째 줄: ".", "..", "..." 순환 대기 애니메이션
- viewLessonStudyDetail 확인 직후: 확인 문구가 초록색으로 나타나고 약 5초 동안 흰색으로 변한 뒤 대기 상태로 복귀
- 세 번째 줄: 기존 로컬 경과 시간 기준 진행바. 첫 번째 줄의 서버 학습률과 다를 수 있음
- TTY가 아닌 출력 환경: ANSI 커서 이동 없이 단일 진행 줄만 갱신
- NO_COLOR 환경 변수: 색상 비활성화

4) 과제 조회

- 메뉴 4: 교과 과목을 순회하여 status가 미제출 또는 진행중인 과제 출력
- 메뉴 6: 전 과목에서 현재 날짜가 제출 기간 안에 있고 제출 완료되지 않은 과제 출력
- 메뉴 7: 메뉴 6과 같은 과제를 선택한 뒤 상세 HTML의 과제내용 본문만 출력
- 메뉴 4, 6, 7의 과제 목록과 상세 조회 시작 문구는 과제 제목 안의 n주차/[n주차] 패턴을 [n 주차] 형식으로 표준화합니다.
- 주차를 찾지 못한 과제 제목은 그대로 표시합니다.

5) 강의자료 다운로드 및 상세 분석

- 메뉴 8은 과목별 강의자료 목록을 listScale=1000으로 불러온 뒤 사용자가 여러 항목을 선택할 수 있습니다.
- 이전 메뉴 8(일괄 다운로드)과 메뉴 9(request 기반 상세 분석)는 현재 메뉴 8 하나로 통합되었습니다.
- 선택된 강의자료는 먼저 client.getMaterialAttachments()로 첨부파일을 미리 분석하고, 첨부가 있는 항목만 다운로드 큐에 넣습니다.
- 저장 경로는 downloads/<과목명>/강의자료들/<강의자료명>/ 입니다.
- 강의자료 상세 HTML에서 첨부 후보 링크를 추출하는 파서는 parseEcampusClassroomAttachmentsHtml() 입니다.
- 첨부 링크 후보는 첨부/파일/다운로드 문맥을 가진 앵커와 버튼 중심으로 찾습니다.

- 메뉴 8의 첨부 분석은 request 객체를 직접 활용해 상세 분석을 수행합니다.
  - 과목 선택 → 강의자료 다중 선택
  - request로 /bbs/bbsLect/viewAtcl POST → 상세 fragment 획득
  - parseEcampusClassroomAttachmentsHtml로 첨부 목록 추출 및 미리보기 출력
  - 확인 후 다운로드 (preloadedAttachments로 중복 fetch 최소화)
- 최근 분석(2026-06): unpacked SAZ 패킷 헤더(files/e러닝-expanded/sessions/*.md)에서 navigation 스타일 POST 헤더를 참고하여 요청 개선.
  - sec-ch-ua*, Sec-Fetch-Mode: navigate, full Accept, Cache-Control 추가
  - X-Requested-With 제거 (viewAtclForm은 form submit navigation)
  - Referer를 classRoomMainForm 스타일로 조정
- 발견: viewAtclForm 직접 POST 응답은 shell(#bbsAtclView + hidden atclId + JS)만 반환.
  - 실제 제목/본문/첨부는 후속 JS load("/bbs/bbsLect/viewAtcl", "/bbs/bbsLect/atclList" 등)로 동적 로드.
  - 따라서 단일 POST만으로는 parser가 attachments를 찾지 못하는 경우가 많음 (샘플에서도 0).
- 로컬 샘플: tmp-sample-material-detail-another.html (다른 과목의 실시간 강의자료 상세 HTML, hasAttachment=true).
  - 이전 샘플(tmp-sample-material-detail.html)은 제거.
- prompt-client의 "4. 강의실자료 (materials)"로 목록 JSON(request 포함)을 확인한 뒤, auto-manager 메뉴 8로 상세 분석/다운로드 연계 가능.

메뉴 7 본문 처리:

- .inline.field 중 label.label-title 텍스트가 "과제내용"인 영역 선택
- 내부 .note-editable만 선택
- script, style, noscript 제거
- br과 p/div/li/h1~h6/blockquote/pre/tr를 줄바꿈으로 정리
- 연속 공백 정리 및 빈 줄 제거
- 원문은 요약하거나 다시 작성하지 않음
- 숫자 목록은 노란색, <제출물> 형태 소제목은 청록색, *, -, • 목록 기호는 초록색
- LMS 템플릿 변경으로 .note-editable을 찾지 못하면 경고 출력

[5. ElearningSession 동작 순서]

src/ecampus/elearning.ts의 ElearningSession은 단일 차시의 학습 기록 라이프사이클을 처리합니다.

1. lessonNewWindow 호출
2. viewLessonCmnt 호출
3. 최초 addStudyRecord 호출: 60초
4. 응답의 prgrRatio를 서버 학습률 표시값에 반영
5. 응답에서 studyDetailId 확보
6. 첫 주기 갱신: 25~35초 후
7. 이후 주기 갱신: 45~75초 간격
8. 각 갱신 시 누적 시간을 60초 증가
9. addStudyRecord 응답의 prgrRatio로 서버 학습률 갱신
10. 각 갱신 후 viewLessonStudyDetail 호출
11. 종료 시 exitStudy 호출

서버 응답에 prgrRatio가 있으면 progressPercent에 숫자로 반영하고, 화면 표시용 progressPercentText에는 원본 소수점 형식을 보존합니다.

[10. 현재 확인된 유지보수 주의점]

1) 메뉴 5의 stdNo 기본값

- 메뉴 5는 전 과목 큐를 만들지만 stdNo 기본값은 queue[0]의 crsCreCd를 기준으로 한 번만 생성합니다.
- 이후 다른 과목에도 같은 stdNo 문자열을 전달합니다.
- stdNo 규격이 과목별 crsCreCd를 요구하는지 실제 요청으로 확인해야 합니다.
- 이 문서 갱신 작업에서는 코드 수정하지 않았습니다.

2) 목록 페이지 크기

- getAssignmentList() 기본 listScale은 10입니다.
- getElearningLessonListHtml()도 lessonList 요청에 listScale 10을 사용합니다.
- 항목이 10개를 넘는 과목에서 서버가 전체 목록을 반환하는지, 페이지 처리 보완이 필요한지 확인해야 합니다.

3) 쿠키 유효성 판단

- isCookieJarUsable()은 만료되지 않은 쿠키 존재 여부를 확인합니다.
- 서버 세션이 실제로 살아 있는지는 후속 요청에서 판별됩니다.
- auto-manager는 로그인 관련 오류가 발생하면 자동 재로그인을 시도합니다.

4) 과제 상세 템플릿 의존성

- 메뉴 7은 label.label-title="과제내용"과 .note-editable 구조를 사용합니다.

[13. Live Capture 분석 결과 (2026-06-05, scripts/capture-live.mjs + 사용자 직접 작업)]

사용자가 "지금 생성된 html 파일들 없애고" 요청 후, puppeteer visible 브라우저로 직접 로그인→과목→강의자료 탭→특정 자료 클릭→첨부 다운로드까지 수행.
scripts/capture-live.mjs 가 RELEVANT_PATHS (viewAtclForm, viewAtcl, atclList, classRoomAtclList, bbsLect, materials 등) 및 attachment 응답을 자동으로 captures/live/<ts>_<slug>/ 에 저장:
- request.json (url, method, headers, postData)
- response.json (status, headers)
- response-body.html (또는 .json)
- page.html (capture 시점의 전체 DOM)
- 실제 다운로드 파일 (content-disposition attachment 또는 바이너리 감지 시)

주요 발견 (authentc 트래픽):

1. 목록 구조 차이
   - client.getMaterialList() 가 사용하는 POST /bbs/bbsLect/atclList 응답 fragment:
     <li class="itemli" onclick="javascript:viewAtcl('ATCL_xxx', null, '10291');"> ... <a href="javascript:void(0)"><span>[n주차] 제목</span><i class="paperclip icon"></i></a>
     (onclick 이 li 에 있고, 첫 인자는 atclId, bbsId 는 페이지 hidden #bbsId 에 있음)
   - classRoomAtclList 또는 atclListForm 페이지:
     <a href="javascript:viewAtcl('BBS_xxx','ATCL_xxx');">
   - 기존 parseBbsListHtml 의 $("a[href^='javascript:viewAtcl']") 는 /atclList fragment 에서 0개 매치 → 목록이 비거나 id/request 가 틀림.
   - parseFunctionArguments 도 onclick 인자 순서 가정 (bbs first)이 /atclList 에서 깨짐.

2. 상세 내용 로딩 (동적 shell + ajax)
   - 브라우저에서 자료 클릭 시 (ajax flow): viewAtcl() JS 가 $("#bbsAtclView").load( "/bbs/bbsLect/viewAtcl", {formType:"VIEW", bbsId:$("#bbsId").val(), atclId, bbsCd:"PDS", crsCreCd} )
   - /bbs/bbsLect/Form/viewAtclForm (GET query 또는 POST) → 전체 레이아웃 shell (head에 모든 css/js, #bbsAtclView placeholder, hidden form fields) 만 반환. 제목/본문/첨부 없음.
   - /bbs/bbsLect/viewAtcl POST 응답 (text/html fragment, X-Requested-With 있음):
     <div class="post_view">
       <h4 id="atclTitleText">제목</h4>
       <ul class="viewInfo">작성자/작성일/조회수</ul>
       <ul class="viewInfo file">
         <li><a href="javascript:fileDown('Y0Yrae3kKH-KAyjvh_sBEQ==');"><i class="paperclip icon"></i>LC06장 논리식의 간소화_v10.pdf</a></li>
       </ul>
       <div class="content-field" id="atclCtsText">본문</div>
       ...
     </div>
   - 따라서 이전 fetchClassroomDetailHtml (request.body 로 Form/viewAtclForm 에 POST) + parseAttachments 는 항상 attachments:0 이었음.

3. 첨부 다운로드
   - fileDown(token) JS (common.js 등에 정의, 페이지에 hidden form + iframe _m_download_iframe 있음): form action = /file/download/TOKEN , submit to iframe.
   - 응답: GET /file/download/<base64-token>?   (capture 시 referer 는 viewAtclForm?bbsId=...&atclId=... url)
     Headers: content-disposition: attachment; filename="..."; filename*=UTF-8''<urlencoded.pdf>
     content-type: application/octet-stream
     content-length: 실제 크기
   - capture script 가 binary 감지 시 파일 저장 시도 (일부 경우 filename 파싱/인코딩 문제로 capture dir 에는 저장 안 될 수 있음. 브라우저 기본 다운로드 폴더에는 남음).

4. 헤더 관찰
   - /viewAtcl POST: X-Requested-With: XMLHttpRequest, Content-Type: application/x-www-form-urlencoded, Accept: text/html, */*;q=0.01 , sec-ch-ua* , referer=Form viewAtclForm url
   - download GET: upgrade-insecure-requests, no X-Requested-With (navigation-like), full sec-ch-ua

5. 코드 영향 및 수정
   - parseBbsListHtml: li[onclick] 지원 + 인자 순서( ATCL first vs BBS first) 처리 + options.bbsId 주입으로 bbsId 복원. request 를 실제 content fetch 용으로 /bbs/bbsLect/viewAtcl + {formType:"VIEW", bbsCd, ...} 로 생성 (item.url 은 Form 유지).
   - login.ts getMaterialList/getNoticeList: bbsId 를 parse options 에 전달.
   - SAZ parse 경로에도 bbsId 전달.
   - extractUrlCandidate: fileDown('TOKEN') → /file/download/TOKEN 절대 URL 생성.
   - looksLike* : fileDown / /file/download/ 지원.
   - fetchClassroomDetailHtml / getMaterialAttachments: 이제 올바른 endpoint 로 content fragment 를 받아 parse 가능.
   - auto-manager 메뉴 8 통합 기능이 실제 첨부 추출/미리보기/다운로드 동작.
   - 기존 SAZ fixture 기반 테스트 expectation 갱신 (request.url 과 body 에 formType/bbsCd 추가).
   - docs/api-responses/materials.json 예시도 갱신.

이제 request 객체만으로 (getMaterialList 후 pick → getMaterialAttachments) 실제 파일 URL 과 다운로드가 가능해짐. (정적 fetch + 인라인 HTML 시도는 폐기, live authentic 트래픽 기반으로 전환)
