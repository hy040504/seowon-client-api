1. 프로젝트 목적

이 프로젝트는 서원대학교 e-campus 사이트와 연동하기 위한 Node.js/TypeScript 패키지 형태의 클라이언트 API이다.
현재까지 구현된 핵심 기능은 다음과 같다.

- e-campus 로그인용 encryptData 생성
- e-campus 로그인 요청 및 쿠키 유지
- 로그인 후 메인 페이지에서 과목 목록 추출
- 과목별 강의실 코드(crsCreCd) 및 타입(crsTypeCd) 추출
- 논리회로 강의실 패킷(.saz) 분석 기반으로 공지사항, 과제, 강의자료실 목록 JSON 추출
- 로그인된 클라이언트에서 공지사항, 과제, 강의자료실 목록을 각각 조회하는 API 형태 설계

사용자는 설명, 주석, 테스트 로그를 가능하면 한국어로 유지하기를 원한다.


2. 현재 기술 스택

7. 로그인 클라이언트 구현 현황

주요 메서드:
- prepareLoginSession()
  로그인 팝업 페이지를 먼저 열어 세션 쿠키를 준비한다.

- login({ userId, password })
  createLoginEncryptData로 encryptData를 만들고 loginWithEncryptData를 호출한다.

- loginWithEncryptData({ encryptData })
  /user/userHome/login으로 로그인 요청을 보낸다.

- getMainPageHtml()
  로그인 후 메인 페이지 HTML을 가져온다.

- getCourseGroups()
  과목을 교과/비교과 그룹으로 나누어 반환한다.

- getCourseList()
  과목 목록을 배열로 반환한다.

- getCourseListJson()
  과목 목록을 JSON 문자열로 반환한다.

- getCourseNamesJson()
  과거 이름 때문에 남아 있는 메서드이다. 현재는 getCourseListJson과 같은 형태의 배열 JSON을 반환하도록 맞췄다.

- getNoticeList(), getNoticeListJson()
  특정 강의실의 공지사항 목록을 반환한다.

- getMaterialList(), getMaterialListJson()
  특정 강의실의 강의자료실 목록을 반환한다.

- getAssignmentList(), getAssignmentListJson()
  특정 강의실의 과제 목록을 반환한다.

- getClassroomResources(), getClassroomResourcesJson()
  공지사항/강의자료실/과제 목록을 한 번에 묶어서 반환하는 기존 통합 API이다.

11. 공지사항/강의자료실/과제 상세 진입 방식

패킷 분석 결과, 대부분 상세 페이지는 단순 GET URL이 아니라 POST 폼 제출로 렌더링된다.
그래서 JSON에는 단순 url만 넣지 않고 request 객체를 함께 넣는다.

공지사항/강의자료실 상세:
  POST /bbs/bbsLect/Form/viewAtclForm
  body:
    bbsId
    atclId
    crsCreCd

과제 상세:
  POST /asmnt/asmntLect/Form/asmntStuMain
  body:
    asmntCd
    goUrl
    crsCreCd
    userNo
    userName
    rltnCd

주의:
- 상세 접근은 로그인 쿠키가 필요하다.
- 저장된 패킷에서 파싱한 JSON은 요청 재현 정보를 담는 것이며, 실제 상세 HTML을 가져오려면 로그인된 EcampusClient와 쿠키가 있어야 한다.

14. 중요한 구현 메모

1) SAZ 파싱
- 처음에는 fflate를 사용했으나 현재 SAZ에서 Array buffer allocation 오류가 발생했다.
- adm-zip으로 교체했고 정상 동작한다.
- adm-zip은 runtime dependency이다.

2) 한글 깨짐
- 이전 파일 일부는 PowerShell 출력에서 깨져 보일 수 있다.
- 새로 작성한 테스트와 handover 문서는 한국어 UTF-8 기준으로 작성했다.
- package.json description은 현재 콘솔에서 mojibake로 보인다. 기능에는 영향 없지만 나중에 정리해도 된다.

3) getCourseNamesJson 의미 변경
- 초기에는 교과/비교과 과목명 배열 객체를 반환했다.
- 사용자의 최신 요구에 따라 현재는 title/crsCreCd/crsTypeCd 배열 JSON을 반환한다.
- 호환성이 중요해지면 getCourseNamesJson의 이름을 deprecated 처리하고 getCourseListJson 사용을 권장하면 된다.

4) 교과/비교과 구분
- crsTypeCd가 가장 안정적인 기준이다.
- UNI는 교과, CO는 비교과이다.
- CE_로 시작하는 crsCreCd는 현재 저장본 기준 비교과 코드 형태이다.

5) 게시판 ID 생성 규칙
- 교과 강의실 공지사항: BBS_${crsCreCd}_N
- 교과 강의실 강의자료실: BBS_${crsCreCd}_P
- 이 규칙은 논리회로 패킷에서 확인된 것이다.
- 모든 과목에 100% 동일하다고 단정하기보다는 실제 응답에서 menuBbsInfoList 또는 HTML을 확인하는 기능을 추가하면 더 안전하다.


15. 앞으로 이어서 하면 좋은 작업

1) 특정 과목 선택 후 목록 조회 흐름 자동화
- 현재는 과목 목록에서 crsCreCd를 얻고, 그 crsCreCd로 getNoticeList/getMaterialList/getAssignmentList를 호출할 수 있다.
- 다음 단계는 "과목명으로 선택해서 공지/과제/자료실 조회" 같은 편의 메서드를 만들 수 있다.

예상 API:
  client.getCourseByTitle("논리회로")
  client.getAssignmentListByCourseTitle("논리회로", { userNo, userName })

2) 비교과(CO) 강의실 구조 분석
- 현재 패킷 분석은 논리회로(UNI) 중심이다.
- CO 타입 비교과 강의실은 진입 URL이 다르므로 공지/자료/과제 구조가 같을지 추가 패킷이 필요하다.

3) 상세 게시글/과제 본문 조회
- 현재는 목록과 상세 POST 요청 정보까지만 정리한다.
- 다음 단계로 request 정보를 사용해 실제 상세 HTML을 가져오고 첨부파일 목록까지 파싱하는 기능을 만들 수 있다.

4) 강의자료실 첨부파일 다운로드 안전성 검토
- hasAttachment만 추출한다.
- 실제 다운로드 URL, POST body, 파일명, 파일 크기, 콘텐츠 타입 검증 기능은 아직 없다.

5) 테스트 데이터 경로 안정화
- 현재 test/ecampus-classroom-fixture.ts는 files 아래에서 packet 폴더와 .saz 파일을 탐색한다.
- 폴더명이 바뀌어도 어느 정도 버티지만, 여러 packet 폴더가 생기면 명확한 fixture 경로 지정이 필요하다.

6) README 작성
- 아직 사용법 문서가 충분하지 않다.
- 실제 패키지 사용자 기준으로 설치, 로그인, 과목 조회, 목록 조회 예제를 README에 정리하면 좋다.

17. 다음 AI에게 주의할 점

- 사용자는 실제 동작하는 모듈화를 원한다. 분석만 하지 말고 가능한 경우 코드와 테스트까지 구현하는 흐름을 선호한다.
- 단독 테스트 명령어를 계속 같이 제시해 달라고 요청했다.
- JSON 결과는 테스트 로그로 보여줘야 사용자가 확인할 수 있다.
- 실제 로그인 테스트는 민감 정보와 서버 요청이 있으므로 사용자 요청 없이 실행하지 말 것.
- .env의 비밀번호를 응답에 노출하지 말 것.
- files 폴더의 HTML/패킷은 참고 자료이며 패키지 배포 파일에는 포함하지 않는 방향이 좋다.
- 현재 폴더는 git repository가 아니다. git status/diff는 동작하지 않는다.
