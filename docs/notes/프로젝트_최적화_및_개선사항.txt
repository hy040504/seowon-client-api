[3-1] hope-basket 모듈의 ecampus 의존성 제거 ★ 중요
  - 현재 문제 (잘못된 의존성 방향):
    · src/hope-basket/client.ts → src/ecampus/cookies.ts (쿠키 저장/로드)
    · src/hope-basket/basket.ts → src/ecampus/utils.ts (absoluteUrl)
    · src/hope-basket/saz.ts   → src/ecampus/saz.ts (parseFiddlerSazSessions)

    hope-basket는 독립 모듈이어야 하는데 ecampus에 종속되어 있음.
    이 상태에서 ecampus를 제거하면 hope-basket도 깨짐.

  - 해결 방법:
    공유 유틸리티를 src/shared/ 또는 src/utils.ts 로 분리:
    src/shared/cookies.ts      ← ecampus/cookies.ts 이동
    src/shared/utils.ts        ← ecampus/utils.ts의 공통 함수 이동
    src/shared/saz.ts          ← ecampus/saz.ts의 공통 파서 이동

    그 후:
    · ecampus → src/shared/* 에서 import
    · hope-basket → src/shared/* 에서 import
    → 두 모듈이 서로를 직접 참조하지 않음

[3-2] BaseHttpClient 추상화

## 4. 성능 최적화
================================================================================

[4-1] 쿠키 저장의 동기 I/O 제거 ★ 성능 직결
  - 현재 문제:
    모든 API 요청 성공/실패 직후 await this.persistCookieJar() 호출
    persistCookieJar → saveCookieJarToFile → writeFileSync (동기 디스크 쓰기)
    → HTTP 요청마다 디스크 동기 I/O 발생 = 불필요한 블로킹

  - 해결 방법:
    1) writeFileSync → writeFile (비동기) 변경
    2) 매 요청마다 저장하지 말고, 세션 종료 시 1회 저장 또는
       디바운스(debounce) 방식으로 500ms 지연 후 저장

    예시 (디바운스):
    private _saveCookiesDebounced = debounce(() => {
      writeFile(this.cookieFilePath, JSON.stringify(jar.toJSON()));
    }, 500);

---

[4-2] 대형 JSON 파일 처리 방식 개선
  - 현재 문제:
    프로젝트 루트에 2.73MB(all-courses.json), 2.79MB(all-courses-enriched.json) 존재
    런타임에 전체를 동기 파싱 시 메모리 15~30MB 추가 점유 및 초기화 지연 발생

  - 해결 방법:
    1) 파일 위치 이동: 루트 → db-generator/data/ 또는 data/ 폴더로 이동
    2) .gitignore에 추가 (대형 데이터 파일은 레포에 포함 불필요)
    3) 런타임 사용 시 스트리밍 파싱(stream-json 라이브러리) 또는
       필요한 과목코드만 인덱스로 빠르게 조회하는 경량 인덱스 파일 생성

---

[4-3] Axios 공통 헤더 중복 선언 제거 (성능 + 코드 크기)
  - 현재 문제:
    postSsv(), postForm(), fetchScorePageHtml() 등 각 메서드마다
    동일한 헤더 객체를 매번 new Object로 생성하여 전달

  - 해결 방법:
    Axios 인스턴스 생성 시 defaults.headers에 한 번만 등록:
    this.http = axios.create({
      baseURL: ...,
      headers: {
        'User-Agent': '...',
        'X-Requested-With': 'XMLHttpRequest',
        'Cache-Control': 'no-cache, no-store',
        'Pragma': 'no-cache',
        'Expires': '-1',
      },
    });
    → 각 메서드에서는 Content-Type, Origin, Referer 등 요청별 헤더만 추가

[5-2] 에러 핸들링 방식 통일 (가장 혼란스러운 부분)
  - 현재 문제: 3가지 방식이 혼용됨
    A. throw new Error(...) 방식: ensureAuthenticated(), syncTermContext()
    B. { success: false, message } 반환 방식: addToBasket(), downloadElearningMp4()
    C. silent fallback 방식: loadCookieJarFromFile(), resolveBrowserExecutable()

  - 권장 통일 방향:
    · 라이브러리 API (EcampusClient, HopeBasketClient 메서드): throw 방식
      → 외부 호출자가 try/catch로 명시적 처리

    · 파일 I/O (cookies 로드): silent fallback 허용 (파일 없음 = 정상 상태)
      단, 실제 I/O 에러는 콘솔 경고라도 출력
