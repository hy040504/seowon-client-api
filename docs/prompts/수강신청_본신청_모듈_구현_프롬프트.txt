# 서원대학교 수강신청 본신청 모듈 구현 요청
# (SAZ 패킷 파일 직접 분석 기반 — 실제 HTTP 데이터로 구체화된 버전)

================================================================================
## ★ 최우선 필독: 수강희망바구니 vs 수강신청 본신청 — 절대 혼용 금지
================================================================================

이 두 시스템은 완전히 별개의 기능이다. 코드 작성 중 어느 한쪽의 개념·경로·타입을
다른 쪽에 혼용하면 실제 수강신청이 오작동하므로 아래 기준을 항상 지킨다.

### 기능 정의

  [수강희망바구니] = 이미 구현됨 → src/hope-basket/ + hope-basket-manager.ts
    - 수강신청 전에 미리 담아두는 '예비 바구니'
    - appcsKindCd = 100
    - menuId = M100779 / pgmId = P001609
    - 한국어로: 희망바구니, 예비 담기, 수강희망바구니
    - 이 모듈에는 절대 손대지 않는다.

  [수강신청 본신청] = 이번에 새로 구현 → src/course-registration/ + course-registration-manager.ts
    - 실제로 수강 등록을 확정하는 '진짜 수강신청'
    - appcsKindCd 파라미터 없음 (본신청에는 미사용)
    - menuId = M100780 / pgmId = P001619
    - 한국어로: 수강신청, 본신청, 실제 수강신청
    - 이 모듈만 새로 만든다.

### 엔드포인트 구분표 (혼용 절대 금지)

  기능           | 희망바구니 경로 (건드리지 않음)           | 본신청 경로 (새로 구현)
  -------------|----------------------------------------|----------------------------------------
  담기/등록       | saveHopeAppcsDtls.do                   | saveAppcsDtls.do
  취소           | saveHopeAppcsDtlsCancl.do              | saveAppcsDtlsCancl.do
  내 목록 조회    | findEstblSubjtShpbsList.do             | findAppcsDtlsList.do
  검증(체크)      | findSaplHopeAppcsChk.do (희망바구니용)  | findWarnStdrInqryCscnt.do (본신청용)
  과목 검색       | findEstblSubjtGnrlList.do (M100779)    | findEstblSubjtGnrlList.do (M100780)

  위 표의 희망바구니 경로는 새 모듈에서 절대 사용하지 않는다.
  본신청 경로를 기존 희망바구니 코드에 추가하지도 않는다.

### 타입 접두어 구분표

  희망바구니 타입 (기존, 변경 금지)   | 본신청 타입 (신규 생성)
  ----------------------------------|---------------------------
  SugangSubject                     | CourseRegRegisteredSubject
  SugangBasketMutationOptions       | CourseRegMutationOptions
  SugangBasketMutationResult        | CourseRegMutationResult
  SugangMyHopeBasketListOptions     | CourseRegMyListOptions
  SugangLoginCredentials            | CourseRegLoginCredentials
  SugangLoginResult                 | CourseRegLoginResult
  HopeBasketClientOptions           | CourseRegistrationClientOptions
  HopeBasketClient                  | CourseRegistrationClient

  단, 두 시스템이 공유하는 타입은 기존 것을 그대로 재사용한다:
    - SugangStudentInfo  (로그인 후 학생 정보 — 서버/구조 동일)
    - SugangTermContext  (학년도/학기 문맥 — 구조 동일)
    - SugangAppcsSchedule (수강 일정 — 공통 SSO API 사용)
    - SsvDocument, SsvRow, SsvDataset (SSV 프로토콜 — 완전 동일)

### 파일 소유권 구분

  수정 금지 (희망바구니 소유):          새로 생성 (본신청 소유):
  - src/hope-basket/                  - src/course-registration/
  - hope-basket-manager.ts            - course-registration-manager.ts
  - .seowon-hope-basket.cookies.json  - .seowon-sugang.cookies.json

  src/index.ts → 하단에 새 export 블록 추가만 허용, 기존 export 수정 금지.

## A. SAZ 패킷 분석 결과 요약 (구현의 근거)
================================================================================

분석 파일: SAZ\실제 수강신청\실제 수강신청 페이지 로그인 및 수강신청.saz
         SAZ\실제 수강신청\수강신청 로그인 중 이유없이 비번 오류.saz

### ⚠️ 핵심 발견: 수강신청 본신청도 sugangh.seowon.ac.kr 서버를 사용한다

기존 `src/hope-basket/`은 `sugangh.seowon.ac.kr`에서 menuId=M100779, pgmId=P001609을 씀.
실제 수강신청(본신청)은 같은 서버(sugangh.seowon.ac.kr)에서 menuId=M100780, pgmId=P001619를 씀.
즉, 서버는 동일하지만 메뉴 ID와 프로그램 ID가 다르고, 엔드포인트 경로가 다르다.

| 항목           | 수강희망바구니 (기존)               | 수강신청 본신청 (신규)                |
|--------------|----------------------------------|--------------------------------------|
| 서버           | sugangh.seowon.ac.kr             | sugangh.seowon.ac.kr (동일)          |
| 프로토콜        | Nexacro SSV                      | Nexacro SSV (동일)                   |
| menuId        | M100779                          | M100780                              |
| pgmId         | P001609                          | P001619                              |
| 로그인          | findAppcsLogin.do?menuId=edu     | findAppcsLogin.do?menuId=edu (동일)  |
| 메뉴 접근        | /nx/ (포털)                       | /nx/ (포털, 동일)                    |
| 수강신청         | saveHopeAppcsDtls.do             | saveAppcsDtls.do ← 다름              |
| 수강취소         | saveHopeAppcsDtlsCancl.do        | saveAppcsDtlsCancl.do ← 다름         |
| 내 목록          | findEstblSubjtShpbsList.do       | findAppcsDtlsList.do ← 다름          |
| 과목검색         | findEstblSubjtGnrlList.do        | findEstblSubjtGnrlList.do (동일)     |

### A-1. 실제 수강신청 SAZ 전체 흐름 (330 세션)

#### Phase 1: 최초 접속 및 서버 과부하 오류 (세션 001~090)

- 세션 001: `CONNECT sugangh.seowon.ac.kr:443` → 희망바구니 세션 중
- 세션 066~076: `/nx/` 정적 리소스(JS/PNG) 로드 중 타임아웃 발생
  - 응답: `[Fiddler] The connection to 'sugangh.seowon.ac.kr' failed.`
  - 오류 코드: `Error: TimedOut (0x274c)`
  - 오류 메시지: `System.Net.Sockets.SocketException 연결된 구성원으로부터 응답이 없어 연결하지 못했거나, 호스트로부터 응답이 없어 연결이 끊어졌습니다 211.230.232.1`

#### 비밀번호 오류 파일 상세 (수강신청 로그인 중 이유없이 비번 오류.saz)
- 총 5세션, 그 중 서원대 API: 1세션 (세션 002)
- 세션 002: `POST /com/SsoCtr/findAppcsLogin.do?menuId=edu&pgmId=edu`
  - 요청: `stuno=202311420 | password=hy040504! | appcsKindCd=100`
  - 응답: `ErrorCode:int=0 | dsFlag.flag=0` (ErrorCode는 0이지만 flag=0 = 로그인 실패)
  - 해석: HTTP 레벨은 정상(200 OK)이지만 SSV 내 dsFlag.flag=0으로 로그인 거부

### B-3. `errors.ts` — 실제 패킷 기반 에러 정의

패킷에서 확인된 에러들만 enum으로 정의. `ErrorCode`와 `ErrorMsg` 파싱 로직 구현.

```typescript
/**
 * 수강신청 본신청 에러 유형.
 * 패킷 분석에서 확인된 실제 서버 응답 패턴 기반.
 *
 * SSV 응답 레벨:
 *  - ErrorCode:int=0 이면서 dsFlag.flag=0 → 로그인 실패 (서버 과부하 허위 오류 포함)
 *  - ErrorCode:int=-20001 + ErrorMsg → 수강신청 처리 오류
 *
 * TCP/HTTP 레벨:
 *  - TimedOut (0x274c) → 서버 연결 자체 불가 (과부하 시 발생)
 */
export enum CourseRegErrorType {
  /** ErrorCode=0, flag=0: 로그인 실패 (서버 과부하로 허위 발생 가능) */
  LOGIN_FAILED = "LOGIN_FAILED",
  /** ErrorCode=-20001: 학점 초과 ("총 신청 가능학점 초과이어서 신청할 수 없습니다") */
  CREDIT_LIMIT_EXCEEDED = "CREDIT_LIMIT_EXCEEDED",
  /** ErrorCode=-20001: 이미 신청한 과목 ("금학기에 이미 신청한 교과목입니다.") */
  ALREADY_REGISTERED = "ALREADY_REGISTERED",
  /** ErrorCode=-20001: 정원 초과 (ErrorMsg에서 패턴 확인 필요) */
  CAPACITY_EXCEEDED = "CAPACITY_EXCEEDED",
  /** ErrorCode=-20001: 시간표 충돌 */
  TIME_CONFLICT = "TIME_CONFLICT",
  /** ErrorCode=-20001: 수강신청 기간 아님 */
  NOT_IN_PERIOD = "NOT_IN_PERIOD",
  /** ErrorCode=-20001: 학과 제한 */
  DEPARTMENT_RESTRICTED = "DEPARTMENT_RESTRICTED",
  /** TCP 레벨: TimedOut (0x274c) — 서버 과부하 시 연결 자체 불가 */
  CONNECTION_TIMEOUT = "CONNECTION_TIMEOUT",
  /** 네트워크: ECONNRESET */
  CONNECTION_RESET = "CONNECTION_RESET",
  /** 네트워크: ETIMEDOUT */
  REQUEST_TIMEOUT = "REQUEST_TIMEOUT",
  /** ErrorCode=-20001이지만 알 수 없는 ErrorMsg */
  UNKNOWN_SERVER_ERROR = "UNKNOWN_SERVER_ERROR",
  /** 분류 불가 */
  UNKNOWN = "UNKNOWN",
}

/**
 * SSV 응답 본문을 파싱하여 에러 유형을 분류한다.
 * ErrorCode=0이고 flag=0인 경우 LOGIN_FAILED를 반환한다.
 * @param errorCode - SSV ErrorCode 값 (0 = 성공, 음수 = 오류)
 * @param errorMsg - SSV ErrorMsg 값 (오류 시 한글 메시지)
 * @returns 분류된 CourseRegErrorType
 */
export function classifyCourseRegError(
  errorCode: number,
  errorMsg?: string
): CourseRegErrorType {
  if (errorCode === 0) return CourseRegErrorType.UNKNOWN; // 성공 (호출 측에서 처리)

  const msg = errorMsg ?? "";
  if (msg.includes("학점 초과") || msg.includes("신청 가능학점 초과")) {
    return CourseRegErrorType.CREDIT_LIMIT_EXCEEDED;
  }
  if (msg.includes("이미 신청한 교과목") || msg.includes("이미 신청한")) {
    return CourseRegErrorType.ALREADY_REGISTERED;
  }
  if (msg.includes("정원") && msg.includes("초과")) {
    return CourseRegErrorType.CAPACITY_EXCEEDED;
  }
  if (msg.includes("시간") && (msg.includes("중복") || msg.includes("겹"))) {
    return CourseRegErrorType.TIME_CONFLICT;
  }
  if (msg.includes("기간") || msg.includes("신청 시간이 아닙니다")) {
    return CourseRegErrorType.NOT_IN_PERIOD;
  }
  if (msg.includes("학과") && (msg.includes("제한") || msg.includes("학생만"))) {
    return CourseRegErrorType.DEPARTMENT_RESTRICTED;
  }
  return CourseRegErrorType.UNKNOWN_SERVER_ERROR;
}

/**
 * 에러 유형에 대한 사용자 친화적 한글 메시지를 반환한다.
 * @param errorType - 분류된 에러 유형
 * @param serverMsg - 서버 원본 ErrorMsg (있을 경우 우선 표시)
 * @returns 한글 에러 메시지
 */
export function formatCourseRegError(
  errorType: CourseRegErrorType,
  serverMsg?: string
): string {
  if (serverMsg) return serverMsg; // 서버 메시지 우선
  switch (errorType) {
    case CourseRegErrorType.LOGIN_FAILED:
      return "로그인에 실패하였습니다. 서버 과부하 시 올바른 비밀번호도 거부될 수 있으니 재시도하세요.";
    case CourseRegErrorType.CREDIT_LIMIT_EXCEEDED:
      return "신청 가능 학점을 초과하였습니다.";
    case CourseRegErrorType.ALREADY_REGISTERED:
      return "이미 신청한 교과목입니다.";
    case CourseRegErrorType.CAPACITY_EXCEEDED:
      return "수강 정원이 초과되었습니다.";
    case CourseRegErrorType.TIME_CONFLICT:
      return "시간표가 중복됩니다.";
    case CourseRegErrorType.NOT_IN_PERIOD:
      return "수강신청 기간이 아닙니다.";
    case CourseRegErrorType.DEPARTMENT_RESTRICTED:
      return "해당 학과 학생만 신청 가능한 과목입니다.";
    case CourseRegErrorType.CONNECTION_TIMEOUT:
      return "서버 연결 시간이 초과되었습니다. 수강신청 시간대 서버 과부하일 수 있습니다.";
    case CourseRegErrorType.CONNECTION_RESET:
      return "서버 연결이 끊어졌습니다.";
    case CourseRegErrorType.REQUEST_TIMEOUT:
      return "서버 응답 시간이 초과되었습니다.";
    default:
      return "알 수 없는 오류가 발생하였습니다.";
  }
}
```

### B-6. `client.ts` — CourseRegistrationClient 클래스

기존 `HopeBasketClient`와 구조 동일. SSV 코덱(`src/hope-basket/ssv.ts`)을 재사용한다.

```typescript
/**
 * 수강신청 본신청 전용 클라이언트.
 *
 * 범위:
 * - 포함: 로그인, 수강신청 등록/취소, 내 신청 목록 조회, 개설 과목 검색
 * - 미포함: 수강희망바구니(예비 담기)는 HopeBasketClient를 사용할 것
 *
 * 서버: sugangh.seowon.ac.kr (희망바구니와 동일 서버)
 * menuId=M100780, pgmId=P001619 (희망바구니 M100779/P001609와 다름)
 *
 * 수강신청 시간대 서버 과부하로 인해 아래 현상이 발생할 수 있으며 대응 로직이 포함됨:
 * - TCP TimedOut (연결 자체 불가): 자동 재시도
 * - findAppcsLogin flag=0 (허위 로그인 실패): 자동 재시도 (mayBeFalseError)
 * - ECONNRESET: Connection: close 헤더 사용 + 재시도
 */
export class CourseRegistrationClient {
  // --- 상태 ---
  readonly baseUrl: string;
  readonly cookieJar: CookieJar;
  readonly http: AxiosInstance;
  private readonly cookieFilePath?: string;
  private readonly requestTimeoutMs: number;
  private readonly maxRetries: number;
  private onProgress?: (message: string) => void;
  private credentials?: CourseRegLoginCredentials;
  private term: CourseRegTermContext;
  private student?: SugangStudentInfo;  // 기존 타입 재사용 (희망바구니와 동일 서버)

  constructor(options?: CourseRegistrationClientOptions);

  // --- 세션 관리 ---
  /**
   * 로그인을 수행한다.
   * 서버 과부하로 flag=0이 반환될 경우 maxRetries만큼 자동 재시도한다.
   */
  login(credentials?: CourseRegLoginCredentials): Promise<CourseRegLoginResult>;

  /** 현재 세션이 유효한지 확인하고, 만료 시 자동 재로그인한다 */
  ensureLoggedIn(): Promise<void>;

  // --- 수강신청 핵심 기능 ---
  /**
   * 개설 과목을 검색한다.
   * findEstblSubjtGnrlList API를 사용하며 menuId=M100780을 전송한다.
   */
  searchSubjects(options: CourseRegSearchOptions): Promise<SugangSubject[]>;

  /**
   * 내 수강신청 목록을 조회한다.
   * findAppcsDtlsList API 사용. 희망바구니의 findEstblSubjtShpbsList와 다른 경로.
   */
  getMyRegisteredList(options?: CourseRegMyListOptions): Promise<CourseRegRegisteredSubject[]>;

  /**
   * 수강신청을 등록한다 (saveAppcsDtls).
   * 등록 전 경고 장학생 체크(findWarnStdrInqryCscnt + saveWarnStdrInqrtCscnt)를
   * 수행한다 — 패킷에서 매 신청 전에 반드시 이 흐름이 관찰됨.
   */
  registerCourse(options: CourseRegMutationOptions): Promise<CourseRegMutationResult>;

  /**
   * 수강신청을 취소한다 (saveAppcsDtlsCancl).
   */
  cancelCourse(options: CourseRegMutationOptions): Promise<CourseRegMutationResult>;

  // --- 내부 유틸 ---
  private postWithRetry(path, body, queryParams): Promise<AxiosResponse>;
  private normalizeNetworkError(error): Error;
  private loadCookieJar(): CookieJar;
  saveCookies(): Promise<void>;
  getStudentInfo(): SugangStudentInfo | undefined;
  setCredentials(credentials: CourseRegLoginCredentials): void;
  getCredentials(): CourseRegLoginCredentials | undefined;
}

export function createCourseRegistrationClient(
  options?: CourseRegistrationClientOptions
): CourseRegistrationClient;
```

#### 수강신청 1회 흐름 (패킷 기반 필수 구현)

패킷에서 확인된 실제 수강신청 1건 처리 순서:
```
1. findWarnStdrInqryCscnt (경고장학생 조회 횟수 확인)
2. saveWarnStdrInqrtCscnt (경고장학생 조회 횟수 저장)
3. findMyGLIOList (접속 정보 조회 - columnList=deptCd)
4. findSysdate    (서버 시각 조회)
5. saveAppcsDtls  (실제 수강신청 등록) ← 핵심
6. findAppcsDtlsList (내 목록 새로고침)
```

위 흐름을 `registerCourse()` 메서드에서 순서대로 실행해야 한다.
단, 자동화 목적이라면 3~4번(findMyGLIOList, findSysdate)은 생략 가능.
1~2번(경고장학생 체크)은 서버 로직상 필요할 수 있으므로 포함하는 것이 안전.

### B-9. 코딩 컨벤션 (기존 패턴 필수 준수)

모든 패턴은 `src/hope-basket/` 모듈과 동일하게 맞춘다.

1. **JSDoc**: 모든 export에 한국어 설명 + 영문 태그. WHY 위주.
2. **인터페이스 필드**: 모든 필드에 `// 한국어 단행 주석`
3. **타입 접두어**: `CourseReg` (기존 `Sugang` 타입과 충돌 방지)
4. **raw 필드**: 모든 엔티티 인터페이스에 원본 `SsvRow`/`SsvDocument` 보존
5. **순수 함수**: create*/parse* 함수는 부작용 없는 순수 함수
6. **SSV 재사용**: `src/hope-basket/ssv.ts`의 `encodeSsvRequest`, `parseSsv`, `SSV_EMPTY` 등 import하여 사용
7. **기존 타입 재사용**: `SugangStudentInfo`, `SugangLoginResult`, `SsvDocument`, `SsvRow` 등 희망바구니 타입은 그대로 재사용 가능
8. **쿠키 재사용**: `src/ecampus/cookies.ts`의 `loadCookieJarFromFile`, `saveCookieJarToFile` 재사용
9. **Connection: close**: ECONNRESET 방지를 위해 axios 기본 헤더로 설정
10. **재시도**: `ECONNRESET`, `ETIMEDOUT`, `EPIPE`, `ECONNRESET`, `ERR_NETWORK` → 지수 백오프

## C. 주의사항
================================================================================

1. **기존 코드 수정 금지**: `src/hope-basket/`, `hope-basket-manager.ts`, `auto-manager.ts` 등 기존 파일 수정 불가.
   `src/index.ts`는 하단에 새 export 블록 추가만 허용.

2. **SSV 프로토콜 동일**: 수강신청 본신청도 SSV 프로토콜을 사용한다. `src/hope-basket/ssv.ts`를 import하여 재사용.

3. **서버 동일, menuId 다름**: 서버(sugangh.seowon.ac.kr)는 희망바구니와 동일하나
   모든 API 요청의 쿼리 파라미터는 `?menuId=M100780&pgmId=P001619`를 사용해야 한다.
   로그인(findAppcsLogin) 등 공통 API는 `?menuId=edu&pgmId=edu`를 사용한다.

4. **로그인 허위 실패 대응**: 서버 과부하 시 올바른 자격증명에도 `flag=0` 반환.
   `CourseRegLoginResult.mayBeFalseError=true`로 표시하고 자동 재시도.

5. **타입 이름 충돌**: `Sugang` 접두어(희망바구니)와 `CourseReg` 접두어(본신청)로 명확히 분리.

6. **경고 장학생 체크 흐름**: 패킷에서 수강신청 매 시도 전에 findWarnStdrInqryCscnt→saveWarnStdrInqrtCscnt
   순서가 반드시 선행됨. 이를 registerCourse() 내부에서 처리.

================================================================================
## E. 두 시스템 동시 사용 시 올바른 패턴 (예시)
================================================================================

아래는 두 클라이언트를 동시에 사용할 때 올바른 방식이다.
이 패턴을 README 또는 JSDoc 예시로 활용할 수 있다.

```typescript
import { createHopeBasketClient }          from './src/index.js'; // 희망바구니
import { createCourseRegistrationClient }  from './src/index.js'; // 본신청

// 희망바구니 클라이언트 — 예비 담기 전용 (menuId=M100779)
const hopeBasket = createHopeBasketClient({
  cookieFilePath: '.seowon-hope-basket.cookies.json', // 희망바구니 쿠키
});

// 수강신청 본신청 클라이언트 — 실제 등록 전용 (menuId=M100780)
const courseReg = createCourseRegistrationClient({
  cookieFilePath: '.seowon-sugang.cookies.json',      // 본신청 쿠키 (다름!)
});

// 로그인은 각각 별도로 수행 (같은 서버이지만 세션/쿠키 파일이 다름)
await hopeBasket.login({ stuno: '...', password: '...' });
await courseReg.login({ stuno: '...', password: '...' });

// 희망바구니: 예비 담기 → saveHopeAppcsDtls.do (M100779)
await hopeBasket.addToBasket({ subjtCd: '736082', corseDvclsNo: '01' });

// 수강신청: 실제 등록 → saveAppcsDtls.do (M100780)
await courseReg.registerCourse({ subjtCd: '736082', corseDvclsNo: '01' });
//                                ↑ 같은 과목이라도 각각 별개 API 호출
```

위 예시처럼 두 클라이언트는 완전히 독립적으로 동작한다.
같은 세션이나 쿠키를 공유하지 않으며, 호출하는 API 경로도 다르다.
